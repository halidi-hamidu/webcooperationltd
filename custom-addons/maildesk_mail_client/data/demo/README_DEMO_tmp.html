MailDesk Demo Data (Odoo 18)

Purpose

This demo dataset is designed to make a fresh MailDesk database feel like a real, active corporate email system:

  • convincing inbox content for sales and investor demos
  • onboarding and training with realistic flows
  • development and testing with reliable, consistent records

What You Get (By Design)

Mailboxes & Providers

  • 6 mailbox accounts across 3 providers:
    • IMAP: Support, Info, HR
    • Gmail: Sales, Admin (Gmail labels incl. All Mail)
    • Outlook: Finance (Graph folder ids)
  • 36 folders total (6 per account): Inbox, Sent, Drafts, Archive, Spam, Trash

Messages (3 Tiers)

  • Curated core dataset: 138 realistic, scenario-driven emails across all folders
  • Pro dataset: 3 additional “enterprise-style” emails (invoice + design assets + project update)
  • Bulk dataset: 240 additional emails (40 per mailbox) to simulate volume

Total: 381 emails (maildesk.message_index + 1:1 maildesk.ui_cache).

Note: due to manifest load order, the 3 Pro maildesk.message_index records are defined in 05_message_index_demo.xml so that 08_attachments_demo.xml can safely link attachments via res_id.

Threads

  • 6 realistic threaded conversations implemented via 12 mail.message records
  • Replies carry RFC-like threading headers (In-Reply-To / References) in maildesk.message_index

Tags

  • 7 human-readable hashtags (no numeric or cryptic names):
    • #urgent, #customer, #internal, #finance, #follow-up, #hr, #sales

Attachments

  • 58 realistic attachments (PDF / PNG / XLSX)
  • All attachments are real ir.attachment records linked to the correct message
  • Attachment binaries reuse existing Odoo demo assets via file= (no giant inline blobs)

Installation / Upgrade (Required Scripts Only)

MailDesk demo data loads only when the database is created with demo data enabled.

From /Users/vinni/Projects/maildesk:

  • Upgrade an existing database:

    ./scripts/run18.sh -d <database> -u maildesk_mail_client

  • Fresh install:

    1. Create a new database and enable “Load demonstration data”.
    2. Install maildesk_mail_client from Apps.
    3. (Optional) Run an update to ensure everything is up-to-date:
      ./scripts/run18.sh -d <database> -u maildesk_mail_client

Verification Checklist

Mailbox Accounts

  • MailDesk → Configuration → Mailbox Accounts
    • 6 accounts exist (Support, Sales, Info, Admin, HR, Finance)
    • shared mailboxes show multiple users in the access list

Messages, Cache, and Rendering

  • Open MailDesk and switch between accounts
    • inbox list shows realistic previews, read/unread, stars
    • opening a message renders body from cache (fast, consistent)

Threading

  • Open a known thread (e.g., support or sales conversation)
    • replies expand correctly and are ordered chronologically

Attachments

  • Open a message with attachments
    • PDFs preview/download
    • PNG previews
    • XLSX downloads

Tags

  • MailDesk → Configuration → Tags
    • hashtags render with consistent colors
    • tagged messages show the tag badges in the list/detail

Technical Guarantees (SSOT + Correct Odoo Semantics)

1) SSOT

  • maildesk.message_index contains metadata only.
  • No full email bodies (HTML/text) are stored in maildesk.message_index.

2) UI Cache (Strict 1:1)

  • maildesk.ui_cache exists 1:1 for every maildesk.message_index record.
  • Linking is done strictly via ui_cache.index_id.
  • ui_cache.json_cache structure is always:
    {
  "body": {
    "body_html": "…",
    "body_text": "…",
    "attachments": [
      {"id": 123, "name": "…", "filename": "…", "mimetype": "…", "type": "binary"}
    ]
  }
}
  • TTL fields are consistent (json_cache_until and cache_until) and set to a sensible horizon.

3) Attachments

  • Attachments are real ir.attachment records and are linked to the correct message.
  • The UI cache attachments list uses FileModel-compatible dict entries referencing the attachment id.

4) Threading

  • mail.message records are provided as a lightweight mirror for native Odoo linkage and threading.
  • Each demo email has a corresponding mail.message with:
    • message_id matching maildesk.message_index.message_id
    • parent_id derived from maildesk.message_index.in_reply_to when applicable
    • model='res.partner' and res_id pointing to a reused demo partner (so messages are visible in partner chatter)
  • mail.message.body remains a short placeholder (no body duplication); full content renders from maildesk.ui_cache.

5) Folder/Provider Realism

  • maildesk.message_index.folder matches the corresponding mailbox.folder.imap_name.
  • Provider fields align with the mailbox account provider (IMAP/Gmail/Outlook).

6) Demo Runtime Safety (No External Calls)

This demo database is meant to work out-of-the-box without real Gmail/IMAP/Outlook credentials:

  • All provider sync crons remain enabled (production-like).
  • Demo mailbox accounts are intentionally put into backoff (mailbox.account.backoff_until far in the future), so the cron domains select no accounts → no OAuth/IMAP/Graph calls and no noisy errors.
  • Demo folders are marked as already backfilled (mailbox.folder.backfill_completed_at set), so progressive backfill cron has nothing to do.

If you want to convert the demo mailboxes into real synced mailboxes, configure the provider credentials/hosts and then run the MailDesk “Reset sync state” action on the mailbox account(s) (admin-only). This clears backoff and reboots folders into backfill.

Troubleshooting

No demo emails visible

  • Ensure the database was created with demo data enabled.
  • Confirm the module is installed and updated (./scripts/run18.sh -d <db> -u maildesk_mail_client).

Attachments show no preview/download

  • Verify 08_attachments_demo.xml loads and the message has has_attachments=True.
  • Verify the UI cache attachments array contains dicts (not raw ref() values).

Threading does not expand

  • Verify 06_mail_message_threading_demo.xml is loaded.
  • Verify maildesk.message_index reply headers (in_reply_to, references_hdr) are present and consistent.
